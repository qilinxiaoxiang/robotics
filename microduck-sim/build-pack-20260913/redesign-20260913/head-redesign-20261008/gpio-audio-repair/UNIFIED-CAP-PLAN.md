# 顶壳唯一构建来源（P5 / P6，待限额计算）

当前 USB 顶壳从 `curved-head/curved-cap-final-candidate-world.stl` 生成，而早前音频检查用的是另一个已搬过功放柱的壳，必须停止交替引用这两套整壳。

唯一基底确定为 `curved-head/curved-cap-final-candidate-world.stl`。它已经保留原曲面、OpenRB 四柱、扬声器两柱、原服务开口及下缘导轨修订。新流程保留这些原有特征，不回退到光壳，也不拼接多个完整顶壳。

1. 先分类当前 +16X/+2Z 功放与 USB 壳的实际交集：分别取原生曲壳材料、额外新增材料；新增材料再分为原功放柱与其他新增特征。交集体积必须守恒。只有分类结果才能判定顶部空间，不把全部碰撞归给旧柱。
2. 从原始 `audio-roof-posts-world.stl` 中提取两根原功放柱，轴心 XY 为 `[26.650,-17.287]`、`[39.350,-17.287]`，起点 Z133.585，原柱长16.390/17.575、直径4 mm。使用紧贴圆柱选择器与**真实柱实体相交**；选择器不直接削壳。移除部分再减去原生曲壳，因而原皮不被削掉。
3. 对实际移除材料检查三项必须为零：原皮、扬声器柱、OpenRB 柱。另检查无额外新增和无范围外删除。保留导轨及既有服务开口。删除的是原始姿态的两根柱，不是旋转90°音频支线上的两根柱。
4. 候选新轴来自 `audio-route-candidate.json` 的旋转后轴，再加 `[16,0,2]`：`[42.287,-29.550,135.585]`、`[42.287,-16.850,135.585]`。每根分别生成，OD4、Ø2.1深7.2的盲导孔。仍用 M2.5×8、PCB厚1.57、名义啮合6.43。以原生局部屋顶补片向下逐层限制柱顶，禁止顶出曲面；不缓存一组变换后的场景。
5. 以原始八螺钉头/四螺母实体为唯一五金来源，只移除那两颗旧功放圆柱头，保留其余部件。新两颗功放螺丝显式建模8 mm杆和1.7 mm头。不能把已经旋转过的另一套五金再搬一次。
6. 将两根新柱合并至已移除原功放柱的基底。随后把现有 `apply_usb_service_opening.py` 的明确局部切口重新应用到**这一结果**，输出到本目录新文件，不能再加载旧整壳覆盖。
7. 当前 neck compact route 尚无通过的局部开孔方案；不继承旧失败 trunk 孔，也不为新锚点预开孔。neck owner 将用统一壳定位真实交点后给出明确局部切口。

脚本 `unify_amp_cap.py` 已准备独立 `classify / retire / check-retired / post / assemble / hardware` 模式。只有标准库帮助与语法检查运行过，CAD 部分尚未运行。正式调用必须由 root 分配唯一令牌并套 `run_bounded_cad.py --max-mib 512 --seconds 120`，每次只一模式、一根柱或一对障碍；不得批量启动。

分类若发现原皮也有碰撞，先定位、评估接收高度和接触位置，不能盲目生成新柱；不存在因为旧柱错误而否定所有内部布局的推论。构建后的柱、螺丝、cap 对静态场景、完整关节域、预接线安装、工具、闭壳仍需检查。脚本准备不是打印或制造验收。

当前脚本只允许 `[16,0,2]`，输出统一放 `cap-amp16z2/`。退柱前强制读分类收据，造柱前强制读退柱后的碰撞收据。+3Z 分类使用的旧源码逐字节归档在 `source-snapshots/`，原失败报告和交集模型未覆盖。

`cap-amp16z2/finite-stage-plan.json` 已提取原生壳无碰撞而新增壳失败的12个姿态。最终cap、两根新柱和新两螺丝分别对 `head_yaw_link` / `motor13` 检查，合计96对；它是明确的回归子集，不替代完整229姿态验收。当前未启动任何CAD步骤。
