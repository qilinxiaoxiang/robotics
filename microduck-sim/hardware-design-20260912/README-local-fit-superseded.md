## 选定的整机分工

- **机载电脑：Raspberry Pi Zero 2 W（树莓派）**。Raspberry Pi 是英国的单板计算机厂商。Pi 本地读取姿态和关节、运行已有步行模型、采集和压缩画面、播放声音。它带 2.4GHz Wi-Fi 和 512MB 内存；现有步行 ONNX 文件约 0.77MB，体积本身能够容纳，运行内存和速度另看实测。
- **通信转接：ROBOTIS OpenRB-150**。ROBOTIS 是韩国机器人厂商，DYNAMIXEL 是它的智能舵机系列。OpenRB 在当前教程里运行 USB-to-DYNAMIXEL（USB 转舵机通信）固件。
- **运动：14 个 XL330 负责身体与头颈；要用嘴夹东西，再加第 15 个嘴部舵机（servo actuator）**。每个舵机内部已有驱动电路和角度反馈。BNO085 姿态传感器（IMU，inertial measurement unit）告诉程序身体倾斜、转动情况；芯片技术来自 CEVA，载板厂商需按具体购买型号核对。
- **视觉与计算：一个 Camera Module 3 Wide 单目相机（monocular camera）＋电脑**。相机由 Pi 采集，压缩画面通过已有 Wi-Fi 发给电脑；电脑做目标识别和较重的视觉模型，再把目标速度或动作请求传回 Pi。平衡与关节循环留在 Pi，避免网络延迟进入每一次关节更新。
- **声音：MAX98357A 功放＋独立喇叭**，详见下文。Adafruit 是提供电子模块和接线教程的美国厂商；Pololu 是美国机器人电子模块厂商；Gens ace 是格氏/Tattu 体系的模型动力电池品牌。Bambu Lab（拓竹）制造 RoboClub 使用的 X1 Carbon 打印机。

[Pi 官方规格](https://www.raspberrypi.com/products/raspberry-pi-zero-2-w/)、[社区源码](https://github.com/AI-FanGe/Microduck-build-tutorial/tree/4967821/microduck/src)。

## Pi 为什么还要经过 OpenRB

Pi 上的程序能算出“让编号 3 的舵机转到 30°”。但 XL330 的三根线是电源、地和 DATA（数据），没有 USB 接口。Pi 的 USB 口输出的信号不能靠换一根插头就成为 XL330 能接收的信号。

当前接线中，OpenRB 接收 Pi 从 USB 发来的数据，把它送到舵机的 DATA 线上；发送完成后释放这根线，再接收舵机回复的实际角度。这种一根数据线轮流发送、接收的方式叫 half-duplex（半双工）。真正给电机线圈通电、使轴转到目标位置的电路在舵机里面。

所以这里需要的是 **interface adapter（接口转接器）**。OpenRB 这块板可以由合适的 USB 转 DYNAMIXEL 硬件替代；如果自己做串口收发电路并修改软件，也能由 Pi 控制。它的必要性来自我们现有的接线与软件组合，不能归因为 Pi 算不动或接口数量少。XL330 数据线本来就支持 3.3V，不能把原因简化成“必须从 3.3V 升到 5V”。

电脑接 USB 鼠标时，鼠标内部已经有 USB 接口芯片。我们选的 XL330 没有这套 USB 接口，于是外面需要一个转接器。[XL330 通信电路](https://emanual.robotis.com/docs/en/dxl/x/xl330-m288/)、[OpenRB 默认转接固件](https://emanual.robotis.com/docs/en/parts/controller/openrb-150/)。

## 相机怎么安装

打印 `camera/` 的相机托架和俯仰脚座，以及 `head/` 的新头壳、曲面垫座和内侧压板。新头壳直接修改了当前 3MF 的 `5.obj`（object 6），保留原形状和原安装结构，增加两处 M3 孔和排线开口。

两颗 M3×20 螺丝穿过相机脚座、贴合头壳曲面的垫座、头壳和内压板，用垫圈和防松螺母夹紧。相机自身用四颗 M2 螺丝安装在隔柱上；另一个 M3 螺丝固定俯仰角。镜头前方开放，不在广角视野前加厚框。具体零件与紧固件见 [相机装配说明](camera/README.md)。

- 相机板基准：25×23.862mm，按官方机械图的四个安装孔建模。
- 相机托架和脚座已验证为单一闭合实体，相机板、镜头、后连接器与排线占位无相交。
- 托架相对脚座在 −45° 至 +45°、每 5° 抽检无碰撞。这不是整鸭所有头部姿态的连续运动证明。
- 头壳曲面垫座和内压板基于实际网格生成，局部配合无体积穿透。装配位置与坐标在 `head/validation.json`。
- Pi Zero 2 W 需要 **15-pin → 22-pin camera ribbon cable（15 针转 22 针相机排线）**；采购时不能漏掉。最终长度由从头壳出口到 Pi 的实际路径决定，需要留头部转动的弯曲余量。

单目适合作为第一版。它本身不直接输出可靠的米制深度；可以先在平面上放已知尺寸的标记或物体，通过标定估计相对位置。学习型单目深度模型输出也可能有尺度误差，不能直接等同于夹取距离。双目需要两个同步视角、固定相机间距和标定；Zero 2 W 只有一个 CSI 相机口，不能把两个普通 CSI 模块直接插上。

第一版视频目标是 720p、20fps、约 3Mbps H.264；这是待实测的配置，不是保证值。Zero 2 W 具备硬件 H.264 编码；Wi-Fi 的实际吞吐、丢包与端到端延迟要测。原始 1280×720×3 通道×20fps 画面约 442Mbps，必须压缩后传输。[官方相机软件](https://www.raspberrypi.com/documentation/computers/camera_software.html)。

## 电池和电源怎么安装

旧视频的 6.4V、0–3A 电池不作为此次电源基准：其标称电压超过 XL330 的最高 6.0V，且无法证明整机峰值供电足够。此次电池托盘按 **Gens ace GEA8502S60E2，850mAh、2S 7.4V LiPo** 的厂家最大尺寸公差 63×34×22mm 建模，内腔留到 65×36×24mm。充电时从机器人上拆下，使用匹配的 2S LiPo 平衡充电器；LiFePO4 充电模式不适用。

`battery/` 提供托盘、硬盖和结构垫架。两条 4.8mm 宽绑带穿过现有 `a.obj` 框架的指定槽，在结构边梁前折返，再绕过托盘和硬盖。挡边防止电池滑出，硬盖分散绑带压力，薄软垫消除晃动。不能用螺丝尖端或绑带直接挤压软包电池。

这套结构证明到与 `a.obj` 单件的几何配合。原有薄盖 `p.obj/q.obj` 没有被当成承力安装面。当前没有可信整鸭坐标证明该区域始终不被其它元件或运动关节占用；完整装配检查通过前，不能宣称电池已完全藏入原鸭身。

加入通风电子板和声音盒后，完整外置背包为 **64×86×68.6mm**；68.6mm 是从原框架接触面向外的深度。局部 64 项几何交集检查通过，但这个明显增大的外廓和新增重量仍需整机装配验证。固定方式与六件打印件的顺序见 [电池装配说明](battery/README.md)。

电气路线采用两路独立稳压：

1. 电池经匹配插头和保险线分别进入两个稳压器，原始 7.4V 不接 Pi 或舵机。
2. **Pololu D24V150F5：5V 舵机电源**，通过独立分配线束分段注入 XL330。
3. **Pololu S13V30F5：5V 电子设备电源**，供 Pi、相机和功放。
4. Pi 通过 USB 为 OpenRB 逻辑部分供电。OpenRB 通往动力线束只保留 DATA/GND，断开 VDD；两路 5V 输出不能互连，地线共用。

OpenRB 官方舵机端口总供电额定仅 3A；15 个 XL330 在 5V 下的算术堵转电流合计 22.05A，这不是正常步行电流。换大电池后仍把全机电流穿过 OpenRB，不会解决这个瓶颈。独立稳压、分段注入和实际峰值/温升测量缺一不可。详细料号、接线、电流边界和起测试件见 [电源与声音报告](audio-power/REPORT.md)。

## 鸭叫需要什么

**之前的自装购买清单遗漏了扬声器和功放。**我们的浏览器仿真用电脑扬声器播放声音；官方成品另有音频电路。Pi Zero 2 W、OpenRB 和姿态传感器都没有集成能发出鸭叫的喇叭。

使用 Adafruit **#3006 MAX98357A I²S amplifier（数字音频功放）**和 **#3923 8Ω/1W speaker（扬声器）**。Pi 负责播放声音文件，功放把数字音频转换、放大，喇叭把电信号变成空气振动。硬件约占 30×20×5mm 喇叭加 19.4×17.8mm 功放板，端子和导线另留空间。

功放连接 GPIO18、GPIO19、GPIO21，实体针脚分别为 12、35、40；姿态传感器使用 GPIO2/3，相机使用 CSI，OpenRB 使用 USB，接口不冲突。喇叭两线都接功放输出，不把任何一根当 GND。Pi 配置 `max98357a` 音频驱动后，用低音量 WAV 验证；不能把超过 1W 的长期输出施加给这只 1W 喇叭。[功放](https://www.adafruit.com/product/3006)、[扬声器](https://www.adafruit.com/product/3923)。

## 控制和软件状态

手柄可以省。当前社区仓库已经有键盘输入模式，可通过 Wi-Fi 上的 SSH（secure shell，远程终端）操作。相机视频与声音功能没有在这份社区源码里完成，不能写成已开箱可用。

连接关系固定为：电脑发目标动作 → Pi 本地步行循环 → OpenRB 数据转接 → 舵机；相机画面反方向送电脑；声音在 Pi 本地播放。正式运行前需要补视频传输、非阻塞音频播放、断线停机和真实电流监测，并把现有 7.5V 电机模型参数重新核对到实际 5V 供电。检测到低电压、过热或通信超时后应进入停止状态，不继续追赶过期动作。

RoboClub 原教程确认 **Bambu Lab X1 Carbon、0.4mm 喷嘴、PLA、0.20mm Standard**。本设计的小支架采用 4 道墙、30% gyroid（螺旋曲面填充）；头壳单独切片并加支撑。官方教程配置为 Cool Plate / PLA Plate，现场若实际装的是其它板，必须在 Bambu Studio 同步板型后重切，不能直接用温度不匹配的文件。

## 验收范围

文件中的验证结果分别回答三个问题：零件模型是否闭合、局部配合是否相交、Bambu 是否能生成有效切片。它们无法回答整鸭是否能承受新增重量、线缆是否挡住关节、真实电源是否跌落。

实物就绪判据是：电池固定后手动翻转不滑动；相机视野和排线不受头部运动遮挡/拉扯；关节全行程无碰撞；空载和有支撑动作中所有电源端电压/温升在额定范围；视频、叫声与步行动作同时工作且断网能停止。未取得这些读数之前，本包保持“可打印试装，整机待验收”的状态。
